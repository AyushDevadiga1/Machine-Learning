Part 1: Building Intuition

WHAT is a Decision Tree?

A Decision Tree is a non-parametric supervised learning algorithm that learns a hierarchical set of if-then-else decision rules from data to predict a target variable. It partitions the feature space into axis-aligned rectangular regions, assigning a prediction to each region.

Core Concept: Think of it as a flowchart where each internal node represents a "test" on a feature, each branch represents the outcome of that test, and each leaf node represents a class label (classification) or continuous value (regression).

WHY Decision Trees?

Interpretability: The decision path is transparent and human-readable. You can explain exactly why a prediction was made.

Non-linearity: Can model complex non-linear relationships without explicit feature engineering.

Mixed Data Types: Handles both numerical and categorical features naturally.

No Assumptions: Non-parametric - makes no assumptions about data distribution.

Feature Selection: Automatically performs feature selection by choosing the most informative splits.

Multi-output: Can handle multi-output problems (multiple target variables).

HOW Decision Trees Work - The Mental Model

Imagine you're a doctor diagnosing a disease:

  1. Ask the most informative question first - "Does the patient have a fever?" This question splits patients into two groups and gives you the most information.
  2. Recursively repeat - For each group, ask the next most informative question: "Is white blood cell count elevated?"
  3. Stop when confident - Continue until you have enough information to make a diagnosis with high confidence.
  4. Make prediction - The final group a patient falls into determines your diagnosis.

The algorithm does exactly this: It searches for the feature and threshold that best separates the data at each step, measured by a mathematical criterion (information gain, Gini impurity, etc.).

Key Intuitive Properties

🎯 Greedy Splitting

At each node, the algorithm makes the locally optimal choice without looking ahead. This is computationally efficient but doesn't guarantee the globally optimal tree.

🌿 Recursive Partitioning

The algorithm applies the same splitting logic recursively to subsets of data, creating a hierarchical structure. Each subtree is itself a valid decision tree.

📊 Impurity Reduction

Splits are chosen to maximize purity (or equivalently, minimize impurity) in child nodes. Pure nodes contain samples from a single class.

🛑 Stopping Criteria

Growth stops based on conditions like: maximum depth reached, minimum samples per leaf, or no further impurity reduction possible.

⚠️ Common Misconceptions

  • "Trees always overfit" - Not if properly regularized through max_depth, min_samples_split, pruning, etc.
  • "Trees are always interpretable" - Deep trees with hundreds of nodes are as opaque as black boxes
  • "Trees work well on all problems" - They struggle with smooth linear relationships and extrapolation
  • "The first split is always the best feature" - It's the best for that particular impurity measure and dataset, but may not be the most "important" feature overall

Part 2: Mathematical Foundation

The Formal Definition

Given:

  • Training set: \( \mathcal{D} = \{(\mathbf{x}_i, y_i)\}_{i=1}^{N} \) where \( \mathbf{x}_i \in \mathbb{R}^d \) and \( y_i \in \{1, 2, ..., K\} \)
  • Feature space: \( \mathcal{X} = \mathbb{R}^d \)
  • Target space: \( \mathcal{Y} = \{1, 2, ..., K\} \) for K classes

Goal: Learn a function \( f: \mathcal{X} \rightarrow \mathcal{Y} \) that minimizes prediction error

Tree Structure:

$$T = \{(\text{node}_j, \text{feature}_j, \text{threshold}_j, \text{left}_j, \text{right}_j, \text{prediction}_j)\}_{j=1}^{J}$$

where:

  • \(J\) = number of nodes
  • Internal nodes have feature_j and threshold_j
  • Leaf nodes have prediction_j

Impurity Measures - The Core Mathematics

WHAT is Impurity?

Impurity measures how mixed the classes are in a node. A pure node (impurity = 0) contains samples from only one class. A maximally impure node has equal representation from all classes.

1. Gini Impurity (CART Default)

Definition:

$$\text{Gini}(t) = 1 - \sum_{k=1}^{K} p_k^2$$

where \( p_k = \frac{n_k}{n} \) is the proportion of class \(k\) samples in node \(t\)

Intuition: Probability of misclassifying a randomly chosen sample if labeled according to the distribution in the node.

Derivation:

Probability of picking class \(k\): \(p_k\)

Probability of misclassifying it: \(1 - p_k\)

Total misclassification probability: \(\sum_{k=1}^{K} p_k(1 - p_k) = \sum_{k=1}^{K} p_k - \sum_{k=1}^{K} p_k^2 = 1 - \sum_{k=1}^{K} p_k^2\)

Properties:

  • Range: [0, 1 - 1/K] for K classes
  • Minimum (0): Pure node
  • Maximum (0.5 for binary): Uniform distribution
  • Computational efficiency: No logarithms needed

2. Entropy (ID3, C4.5)

Definition:

$$H(t) = -\sum_{k=1}^{K} p_k \log_2(p_k)$$

Intuition: Expected information content (in bits) needed to specify the class of a random sample from the node.

Connection to Information Theory:

Entropy measures the average "surprise" in observing a class. If \(p_k = 1\) (pure node), there's no surprise (H = 0). If all classes equally likely, maximum surprise.

Properties:

  • Range: [0, \(\log_2(K)\)] for K classes
  • Minimum (0): Pure node
  • Maximum (\(\log_2(K)\)): Uniform distribution
  • More sensitive to probability changes than Gini

3. Misclassification Error

Definition:

$$E(t) = 1 - \max_k(p_k)$$

Intuition: Fraction of samples that would be misclassified if we predict the majority class.

Why rarely used for growing trees:

Less sensitive to probability changes. Gini and Entropy prefer splits that create purer nodes, even if error rate is the same.

Information Gain - Choosing the Best Split

Information Gain (IG):

$$IG(t, s) = I(t) - \frac{n_{\text{left}}}{n} I(t_{\text{left}}) - \frac{n_{\text{right}}}{n} I(t_{\text{right}})$$

where:

  • \(I(t)\) is the impurity of current node
  • \(t_{\text{left}}, t_{\text{right}}\) are left and right child nodes after split \(s\)
  • \(n_{\text{left}}, n_{\text{right}}, n\) are sample counts

Weighted Impurity Reduction:

We weight child impurities by their sizes because a split creating one large pure node and one small impure node is better than creating two moderately impure nodes.

The Split Selection Problem:

$$s^* = \arg\max_{s \in \mathcal{S}} IG(t, s)$$

where \(\mathcal{S}\) is the set of all possible splits (feature + threshold combinations)

HOW to Find the Best Split - The Algorithm

For numerical features:

  1. Sort samples by feature value: \(x_{(1)} \leq x_{(2)} \leq ... \leq x_{(n)}\)
  2. Consider midpoints as candidate thresholds: \(\theta_i = \frac{x_{(i)} + x_{(i+1)}}{2}\)
  3. For each threshold, calculate information gain
  4. Choose threshold with maximum gain

Complexity: \(O(n \log n)\) for sorting + \(O(n)\) for scanning = \(O(n \log n)\) per feature

For categorical features:

For binary split: Test each subset vs its complement. For K categories, there are \(2^{K-1} - 1\) possible splits (exponential!).

Practical solution: For multi-class problems, convert to multiple binary features or use greedy search.

Gini vs Entropy - A Deeper Comparison

Interactive Comparison

Adjust class probabilities to see how Gini and Entropy differ:

🔍 Mathematical Insight: Why Gini ≈ Entropy in Practice

Taylor expansion around p = 0.5:

$$\text{Gini}(p) = 2p(1-p)$$ $$H(p) = -p\log_2(p) - (1-p)\log_2(1-p)$$

Near p = 0.5:

$$\text{Gini}(0.5) = 0.5$$ $$H(0.5) = 1 \text{ bit}$$

Both are approximately quadratic around 0.5, differing only in scaling factor.

Practical Implication: Trees trained with Gini vs Entropy are usually very similar. Gini is computationally cheaper (no log operations), so it's the default in scikit-learn.

The CART Algorithm - Complete Derivation

Classification And Regression Trees (CART) - Breiman et al., 1984

Objective Function:

$$\min_{j,\theta} \left[ \frac{n_L}{n} \text{Gini}(t_L) + \frac{n_R}{n} \text{Gini}(t_R) \right]$$

subject to split: \(x_j \leq \theta\)

Recursive Partitioning:

$$R_m = \{x : x \in R \text{ and split conditions for path to node } m\}$$

Leaf Prediction:

$$\hat{y}_m = \arg\max_{k} \sum_{i: x_i \in R_m} \mathbb{1}(y_i = k)$$

Total Tree Cost:

$$\text{Cost}(T) = \sum_{m=1}^{|T|} n_m \cdot \text{Gini}(t_m) + \alpha |T|$$

where \(\alpha\) is complexity penalty (used in pruning)

Variance Reduction for Regression Trees

For regression, we minimize variance instead of impurity:

$$\text{Var}(t) = \frac{1}{n} \sum_{i \in t} (y_i - \bar{y}_t)^2$$

where \(\bar{y}_t = \frac{1}{n} \sum_{i \in t} y_i\)

Split criterion:

$$\text{Variance Reduction} = \text{Var}(t) - \frac{n_L}{n}\text{Var}(t_L) - \frac{n_R}{n}\text{Var}(t_R)$$

Prediction at leaf:

$$\hat{y}_m = \bar{y}_m = \frac{1}{n_m} \sum_{i \in R_m} y_i$$

This is the mean of samples in the leaf (minimizes MSE).

Part 3: Core Algorithms

Algorithm 1: ID3 (Iterative Dichotomiser 3)

WHAT is ID3?

ID3, developed by Ross Quinlan in 1986, is the foundational decision tree algorithm. It uses entropy and information gain to build the tree and only handles categorical features.

Algorithm: ID3 function ID3(Examples, Target_Attribute, Attributes): // Base cases if all examples have same class: return leaf with that class if Attributes is empty: return leaf with majority class // Calculate information gain for each attribute best_attribute = null max_gain = -∞ for each attribute A in Attributes: gain = InformationGain(Examples, A) if gain > max_gain: max_gain = gain best_attribute = A // Create tree node tree = new Node(best_attribute) // Recursively build subtrees for each value v of best_attribute: examples_v = filter(Examples where best_attribute == v) if examples_v is empty: tree.add_child(v, leaf with majority class) else: remaining_attrs = Attributes - {best_attribute} subtree = ID3(examples_v, Target_Attribute, remaining_attrs) tree.add_child(v, subtree) return tree function InformationGain(Examples, Attribute): H_before = Entropy(Examples) H_after = 0 for each value v of Attribute: examples_v = filter(Examples where Attribute == v) weight = |examples_v| / |Examples| H_after += weight * Entropy(examples_v) return H_before - H_after

⚠️ ID3 Limitations

  • No numerical features: Must discretize continuous variables
  • No pruning: Tends to overfit
  • No missing values: Cannot handle incomplete data
  • Greedy: Locally optimal choices may not lead to globally optimal tree
  • Bias towards multi-valued attributes: Information gain favors features with more distinct values

Algorithm 2: C4.5 (Successor to ID3)

WHAT is C4.5?

C4.5, also by Ross Quinlan (1993), extends ID3 to address its limitations. It introduces gain ratio to handle attribute bias, supports continuous features, handles missing values, and includes pruning.

Gain Ratio - Solving Information Gain Bias

Problem: Information Gain is biased toward attributes with many values (like ID numbers).

Solution - Gain Ratio:

$$\text{GainRatio}(S, A) = \frac{\text{IG}(S, A)}{\text{SplitInfo}(S, A)}$$

where:

$$\text{SplitInfo}(S, A) = -\sum_{i=1}^{n} \frac{|S_i|}{|S|} \log_2 \frac{|S_i|}{|S|}$$

Intuition: SplitInfo is the entropy of the split itself (not the target). It penalizes attributes that split data into many small partitions.

Example:

ID attribute (unique for each sample): High IG but also high SplitInfo → Low Gain Ratio

Good predictive attribute: High IG and moderate SplitInfo → High Gain Ratio

Key C4.5 Improvements: // 1. Handle continuous attributes function FindBestThreshold(Examples, ContinuousAttribute): values = sort(unique values of ContinuousAttribute in Examples) best_threshold = null max_gain_ratio = -∞ // Try midpoints between consecutive values for i = 1 to |values| - 1: threshold = (values[i] + values[i+1]) / 2 gain_ratio = CalculateGainRatio(Examples, threshold) if gain_ratio > max_gain_ratio: max_gain_ratio = gain_ratio best_threshold = threshold return best_threshold // 2. Handle missing values function HandleMissingValues(Examples, Attribute): // Fractional instances: distribute sample across branches // proportional to known value distribution known_examples = filter(Examples where Attribute is not missing) for each value v: probability_v = count(v in known_examples) / |known_examples| // Each missing example contributes fractionally for each missing_example: add (missing_example, weight = probability_v) to branch v // 3. Pessimistic Error Pruning function PruneTree(Tree, PruningSet): for each non-leaf node N in post-order: error_with_subtree = CalculateError(N, PruningSet) error_as_leaf = CalculateErrorAsLeaf(N, PruningSet) // Apply continuity correction for statistical significance adjusted_error_subtree = error_with_subtree + 0.5 * num_leaves(N) if adjusted_error_subtree >= error_as_leaf: ReplaceWithLeaf(N)

Algorithm 3: CART (Classification And Regression Trees)

WHAT is CART?

CART, developed by Breiman et al. (1984), is the algorithm used by scikit-learn. It differs from C4.5 by:

  • Always creating binary splits (not multi-way)
  • Using Gini impurity instead of entropy
  • Using cost-complexity pruning
  • Handling both classification and regression in the same framework
CART Algorithm - Complete Implementation class CARTNode: def __init__(self): self.feature = None self.threshold = None self.left = None self.right = None self.prediction = None self.n_samples = 0 class DecisionTreeClassifier: def __init__(self, max_depth=None, min_samples_split=2, min_samples_leaf=1, min_impurity_decrease=0.0): self.max_depth = max_depth self.min_samples_split = min_samples_split self.min_samples_leaf = min_samples_leaf self.min_impurity_decrease = min_impurity_decrease self.root = None def gini(self, y): """Calculate Gini impurity""" classes, counts = np.unique(y, return_counts=True) probabilities = counts / len(y) return 1.0 - np.sum(probabilities ** 2) def find_best_split(self, X, y): """Find the best feature and threshold to split on""" n_samples, n_features = X.shape if n_samples < self.min_samples_split: return None, None current_gini = self.gini(y) best_gain = 0.0 best_feature = None best_threshold = None # Try each feature for feature_idx in range(n_features): feature_values = X[:, feature_idx] unique_values = np.unique(feature_values) # Try thresholds at midpoints for i in range(len(unique_values) - 1): threshold = (unique_values[i] + unique_values[i+1]) / 2.0 # Split data left_mask = feature_values <= threshold right_mask = ~left_mask # Check minimum samples constraint if np.sum(left_mask) < self.min_samples_leaf or \ np.sum(right_mask) < self.min_samples_leaf: continue # Calculate weighted Gini impurity n_left, n_right = np.sum(left_mask), np.sum(right_mask) gini_left = self.gini(y[left_mask]) gini_right = self.gini(y[right_mask]) weighted_gini = (n_left * gini_left + n_right * gini_right) / n_samples gain = current_gini - weighted_gini # Update best split if gain > best_gain and gain >= self.min_impurity_decrease: best_gain = gain best_feature = feature_idx best_threshold = threshold return best_feature, best_threshold def build_tree(self, X, y, depth=0): """Recursively build the decision tree""" node = CARTNode() node.n_samples = len(y) # Calculate prediction (majority class) classes, counts = np.unique(y, return_counts=True) node.prediction = classes[np.argmax(counts)] # Check stopping criteria if depth >= self.max_depth or \ len(np.unique(y)) == 1 or \ len(y) < self.min_samples_split: return node # Find best split feature, threshold = self.find_best_split(X, y) if feature is None: return node # Split and recurse node.feature = feature node.threshold = threshold left_mask = X[:, feature] <= threshold right_mask = ~left_mask node.left = self.build_tree(X[left_mask], y[left_mask], depth + 1) node.right = self.build_tree(X[right_mask], y[right_mask], depth + 1) return node def fit(self, X, y): self.root = self.build_tree(X, y) return self def predict_sample(self, x, node): if node.feature is None: return node.prediction if x[node.feature] <= node.threshold: return self.predict_sample(x, node.left) else: return self.predict_sample(x, node.right) def predict(self, X): return np.array([self.predict_sample(x, self.root) for x in X])

Complexity Analysis

Time Complexity

Training (Building the Tree):

  • At each node: Find best split across all features and thresholds
  • For feature j: Sort \(n\) samples → \(O(n \log n)\)
  • Try \(O(n)\) thresholds, each requiring \(O(n)\) to compute impurity
  • Per node: \(O(d \cdot n \log n)\) where \(d\) is number of features
  • Total nodes: \(O(n)\) in worst case (completely unbalanced tree)
  • Overall: \(O(d \cdot n^2 \log n)\) worst case
  • Balanced tree: \(O(d \cdot n \log^2 n)\)

Prediction:

  • Traverse from root to leaf
  • Depth: \(O(\log n)\) for balanced tree, \(O(n)\) worst case
  • \(O(\log n)\) average, \(O(n)\) worst case per sample

Space Complexity

  • Store tree structure: \(O(\text{number of nodes})\)
  • Balanced tree: \(O(n)\) nodes
  • Each node stores: feature index, threshold, prediction, child pointers
  • Overall: \(O(n)\)

🔍 Optimization Techniques

Pre-sorting: Sort each feature once at the beginning, then maintain sorted order during splits (used in many implementations).

Histogram-based splitting: Bin continuous features into discrete bins, reducing number of thresholds to try (LightGBM, XGBoost).

Parallel computation: Evaluate splits for different features in parallel (XGBoost, LightGBM).

Approximate splitting: Use sampling to find approximate best splits faster (large datasets).

Part 4: Improvements & Regularization

WHY Do Decision Trees Overfit?

High Model Complexity: Unpruned trees can grow to memorize training data, creating one leaf per training sample in extreme cases.

No Smoothness Constraint: Unlike parametric models, trees have no inherent bias toward simple functions.

Greedy Splitting: Local optimization at each split doesn't consider global tree structure.

Noise Fitting: Trees will happily create splits to perfectly classify noisy or mislabeled examples.

Regularization Techniques

1. Maximum Depth

Parameter: max_depth

Effect: Limits tree height, preventing overfitting by stopping growth early.

Trade-off: Too shallow → underfitting; too deep → overfitting

Typical values: 3-10 for tabular data

2. Minimum Samples Split

Parameter: min_samples_split

Effect: Minimum samples required to split a node. Higher values prevent splitting on small subsets.

Typical values: 2-20 (or 0.01-0.05 as fraction)

3. Minimum Samples Leaf

Parameter: min_samples_leaf

Effect: Minimum samples required in a leaf node. Prevents creating tiny leaves that memorize outliers.

Typical values: 1-10 (or 0.005-0.02 as fraction)

4. Maximum Features

Parameter: max_features

Effect: Number of features to consider when finding best split. Introduces randomness (used in Random Forests).

Values: int, float, "sqrt", "log2", None

5. Minimum Impurity Decrease

Parameter: min_impurity_decrease

Effect: Minimum improvement in impurity required to make a split.

Formula: \(\Delta I \geq \epsilon\)

6. Maximum Leaf Nodes

Parameter: max_leaf_nodes

Effect: Limits total number of leaf nodes, controlling tree size.

Note: Tree grows in best-first manner (highest impurity reduction first)

Pruning Strategies

WHAT is Pruning?

Pruning is the process of removing subtrees from a fully-grown tree to reduce overfitting. Unlike early stopping (pre-pruning), pruning grows the tree fully and then simplifies it (post-pruning).

1. Reduced Error Pruning

Algorithm:

  1. Grow tree to maximum depth on training set
  2. For each internal node (bottom-up):
    • Temporarily replace subtree with leaf (majority class)
    • Evaluate accuracy on validation set
    • If accuracy doesn't decrease, make replacement permanent
  3. Repeat until no improvement possible

Pros: Simple, intuitive, usually effective

Cons: Requires separate validation set (reduces training data)

2. Cost-Complexity Pruning (CART)

Objective Function:

$$R_\alpha(T) = R(T) + \alpha |T|$$

where:

  • \(R(T) = \sum_{m=1}^{|T|} n_m \cdot \text{Gini}(t_m)\) is the training error
  • \(|T|\) is the number of leaf nodes
  • \(\alpha \geq 0\) is the complexity parameter

For each subtree rooted at node \(t\):

$$\alpha_{\text{eff}}(t) = \frac{R(t) - R(T_t)}{|T_t| - 1}$$

This is the cost per leaf of keeping the subtree vs collapsing to a leaf.

Minimal Cost-Complexity Pruning Algorithm:

  1. Compute \(\alpha_{\text{eff}}(t)\) for all internal nodes
  2. Prune node with smallest \(\alpha_{\text{eff}}\)
  3. Repeat to get sequence of nested trees: \(T_0 \supset T_1 \supset ... \supset T_k\)
  4. Use cross-validation to select best \(\alpha\)
Cost-Complexity Pruning Implementation def cost_complexity_pruning(tree, alpha): """ Prune tree using cost-complexity criterion Returns: pruned tree """ def compute_alpha_eff(node): if node.is_leaf(): return float('inf') # Error if node is collapsed to leaf error_as_leaf = node.n_samples * gini(node.samples) # Error with subtree error_with_subtree = compute_subtree_error(node) # Number of leaves in subtree n_leaves = count_leaves(node) # Effective alpha for this node alpha_eff = (error_as_leaf - error_with_subtree) / (n_leaves - 1) return alpha_eff def prune_weakest_link(node): """Find and prune node with smallest alpha_eff""" min_alpha = float('inf') weakest_node = None # Traverse tree to find weakest link for n in traverse(node): if not n.is_leaf(): alpha_eff = compute_alpha_eff(n) if alpha_eff < min_alpha: min_alpha = alpha_eff weakest_node = n if weakest_node: collapse_to_leaf(weakest_node) return min_alpha # Generate sequence of pruned trees trees = [tree.copy()] alphas = [0.0] current_tree = tree.copy() while not current_tree.is_leaf(): alpha_eff = prune_weakest_link(current_tree) trees.append(current_tree.copy()) alphas.append(alpha_eff) # Select tree with specified alpha for i in range(len(alphas) - 1): if alphas[i] <= alpha < alphas[i+1]: return trees[i] return trees[-1] # Usage with cross-validation from sklearn.model_selection import cross_val_score def find_best_alpha(X, y): alphas = np.logspace(-5, 1, 100) scores = [] for alpha in alphas: clf = DecisionTreeClassifier(ccp_alpha=alpha) score = cross_val_score(clf, X, y, cv=5).mean() scores.append(score) best_alpha = alphas[np.argmax(scores)] return best_alpha

Feature Engineering for Trees

🔍 Key Insight: Trees vs Linear Models

Linear Models: Benefit greatly from feature engineering (interactions, polynomials, normalization)

Trees: Automatically capture interactions and non-linearity, but have limitations:

❌ Don't Need

  • Normalization/Scaling: Trees are invariant to monotonic transformations
  • Polynomial features: Trees capture non-linearity naturally
  • Simple interactions: Trees will find them

✅ Can Help

  • Domain knowledge features: Ratios, differences that encode expert knowledge
  • Temporal features: Extract year, month, day from dates
  • Categorical encoding: Target encoding, frequency encoding
  • Missing value indicators: Binary flag for missingness

Handling Class Imbalance

1. Class Weights

Modify Gini impurity to be weighted:

$$\text{Gini}_{\text{weighted}}(t) = 1 - \sum_{k=1}^{K} w_k p_k^2$$

where \(w_k\) is the weight for class \(k\)

Balanced class weights:

$$w_k = \frac{n_{\text{samples}}}{n_{\text{classes}} \times n_{\text{samples}_k}}$$

This gives more weight to minority classes in impurity calculations.
